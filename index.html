Alfie

An on-device AI file intelligence agent that learns how you name and organize files — built with an Apple acquisition thesis at its core.

Core thesis

The behavioral dataset Alfie collects — failed searches mapped to correct files, rename decisions, folder choices — is the irreplaceable acquisition asset. The app is the collection vehicle.

The problem

On macOS, files accumulate over years across downloads, email attachments, cloud syncs, and project exports. The result: a personal file system that no longer reflects how you actually think about your work.

Spotlight searches fail because file names don't match how you'd describe them today. Finder's folder hierarchy reflects the logic you used three years ago. The gap between "how I'd search for this" and "how this file is actually named" widens with every new document.

The friction

Semantic mismatch

You search for "Q3 investor update" but the file is named "deck_final_v3_REAL.pptx". No search engine can close that gap without behavioral context.

The gap

No one has solved it natively

macOS tools solve indexing and organization separately. No product connects failed search intent to successful file retrieval to learn from the delta.

The insight

The behavioral gap between how people search and how files are named is a dataset problem — not a search algorithm problem. Every failed search followed by a successful manual retrieval is a labeled training pair.

Alfie's core insight: collect that dataset at scale, on-device, and you've built something Apple can't replicate from their own telemetry. Apple has file access. They don't have intent-labeled file access.

Product design

Alfie is a macOS-native app that runs quietly in the background, watches the file system, and builds an on-device intent graph. Three principles drove every design decision:

Principle 1

Feel like macOS, not an agent

The product integrates with Spotlight, Quick Look, and the Finder toolbar. It shouldn't feel like AI software — it should feel like macOS got smarter.

Principle 2

Privacy by architecture

All inference runs on-device via Core ML and Apple's Neural Engine. The Claude API receives only on-device-generated metadata summaries — never raw file content.

Principle 3

Never touch a file without confirmation

Alfie suggests. The user decides. Every rename, move, and organization action requires explicit approval — the dataset is built from consent, not automation.

Principle 4

The dataset is the moat

Features can be copied. A corpus of 10M+ failed search → correct file mappings, collected with user consent, cannot. Product decisions prioritize dataset quality over feature count.

Architecture

The technical architecture is designed for two things: acquisition readiness and privacy compliance. Everything inference-related runs on the device; the intent graph never leaves.

File intelligence

FSEvents + SQLite FTS5

Real-time file system monitoring feeds a full-text search index with content fingerprinting for duplicate detection.

On-device AI

Core ML + Vision

Apple Silicon Neural Engine runs classification and OCR locally. No file content leaves the device.

Intent graph

Three-table SQLite schema

Files, interactions, and preferences — the behavioral dataset that grows with every Alfie session.

Cloud intelligence

Claude API (metadata-only)

Semantic suggestions use Claude for natural language understanding, but only receive on-device-generated summaries, never file contents.

Step 1

The Problem We're Solving

Most people's file systems are a reflection of how they organized things years ago, not how they think about their work today. Downloads pile up. Email attachments land wherever the OS decides. Project folders branch into sub-folders that made sense at the time.

The result: finding a specific file requires remembering not just what the file contains, but what you named it, when you saved it, and which folder hierarchy you were using at that moment in time. Spotlight helps — but only when your search terms match your naming convention. They rarely do.

The root problem: there is no product on macOS that bridges the gap between "how I think about this file today" and "how this file was named and stored." Alfie closes that gap.

Core use cases

  • Finding a file you know exists but can't locate by name
  • Discovering duplicates from years of saving "final" versions
  • Getting suggestions to rename or reorganize files so future searches work
  • Understanding what's taking up space and why
  • Knowing which files are stale, redundant, or worth archiving

Step 2

Target User

Alfie is for knowledge workers who use macOS seriously — people who generate, receive, and manage large volumes of documents across professional and personal contexts.

The target user is not defined by profession. They're defined by behavior: they've had the experience of knowing a file exists and failing to find it. That experience is nearly universal among people who've used a computer for more than three years.

Primary persona signals

  • 3+ years of accumulated files across multiple contexts (work, personal, side projects)
  • Frequent document creation — writing, spreadsheets, presentations, PDFs
  • Has experienced "I know this file exists" frustration at least monthly
  • Values their time and is willing to pay for tools that save it
  • Not particularly invested in manual file organization — they don't want to curate, they want to find

Secondary audience: Apple itself. Alfie's design explicitly targets acquisition. The behavioral dataset Alfie builds is the product Apple cannot build internally — user-consented, intent-labeled file interaction data at scale.

Step 3

Core Features

Semantic file search

Natural language search that understands intent, not just keywords. "The proposal I sent to the Toronto client in March" resolves to the correct file even if it's named "TOR_proposal_draft4.docx".

Rename assistant

Alfie observes how you find files and suggests renames that align with how you'd search for them. Every suggestion requires explicit user approval — Alfie never renames automatically.

Smart folder suggestions

Based on observed file patterns, Alfie recommends folder structures that match your actual working behavior, not generic templates.

Duplicate detection

Content fingerprinting identifies files with identical or near-identical content regardless of name. Surfaces them for user review and consolidation.

Proactive surfacing

Alfie notices when you're working on something and surfaces related files you haven't opened recently — the brief from last quarter, the template you always re-create.

Optimization score

A dashboard metric that reflects the health of your file system: duplicates, unnamed files, stale downloads, files that have been searched for but not found. Improves as Alfie learns and as the user acts on suggestions.

Step 4

Technical Architecture

File system layer

  • FSEvents API — real-time monitoring of file system changes without polling
  • SQLite with FTS5 — on-device full-text search index, updated continuously
  • CryptoKit fingerprinting — content hashing for duplicate detection

Intelligence layer

  • Apple Vision framework — on-device OCR for scanned PDFs and image-based files
  • Core ML — file classification and intent prediction, runs on Neural Engine
  • Claude API — semantic understanding using on-device-generated summaries only; raw file content never transmitted

Intent graph (the acquisition asset)

  • files table — indexed file metadata, content summaries, tags
  • interactions table — every search query, open, rename, move, with timestamps
  • preferences table — inferred user patterns, naming conventions, folder logic

OS integration

  • Spotlight Extension API — Alfie results appear natively in Spotlight
  • Quick Look Extension — AI-generated preview panel in Finder
  • FileProvider API — iPhone Files app integration (Phase 3)
  • WidgetKit + Handoff — cross-device presence (Phase 3)

Security constraint: The Claude API receives only on-device-generated metadata summaries. File names, sizes, and AI-generated descriptions are permitted. Raw file contents are never transmitted to any external service.

Step 5

Compliance and Privacy

Consumer file management operates in a regulatory gray area — personal files can contain sensitive personal and financial data without the user necessarily recognizing it. Alfie's architecture is designed to make privacy a feature, not just a policy.

Architecture-level controls

  • All file content analysis runs on-device; no file content transmitted externally
  • Intent graph data stored locally; never synced to Alfie servers in identifiable form
  • Aggregated, anonymized behavioral signals are the only data that leaves the device — and only with explicit user consent at onboarding

User-level controls

  • No automatic file operations — every rename, move, and organization action requires explicit user approval
  • Folder exclusions: users can exclude any directory from Alfie's index
  • Full data export and deletion at any time
  • Privacy policy written and published before any external beta

Distribution strategy

Initial distribution outside the Mac App Store (direct download, like Hazel and CleanMyMac) to avoid App Store sandboxing restrictions that would prevent full FSEvents access. App Store submission follows once the permission model is well-tested.

Step 6

Go-to-Market

Phase 1: Private beta (0–500 users)

Direct outreach to knowledge workers with visibly disorganized file systems. Focus on people who describe the "I know this file exists" problem unprompted. Goal: validate core semantic search and collect first 50,000 intent graph events.

Phase 2: Public beta (500–5,000 users)

Product Hunt launch. Focus on macOS power users — developers, writers, consultants, financial professionals. Pricing: free during beta, $8–12/month at launch (competitive with Hazel, CleanMyMac).

Phase 3: Growth (5,000–50,000 users)

App Store submission. Integration with iCloud Drive. Referral mechanics. Partnership conversations with productivity tool makers.

Acquisition trigger

Alfie initiates acquisition conversations when the intent graph reaches meaningful scale — 10,000+ active users generating labeled behavioral data — not at a feature milestone. The dataset maturity is the signal, not the roadmap completion.

Step 7

Metrics and Success

Dataset quality metrics (acquisition-facing)

  • Total labeled intent pairs (failed search → correct file retrieval)
  • Active users generating behavioral signal (30-day cohort)
  • Intent graph coverage (% of user file types represented)
  • Model accuracy improvement rate (semantic search precision over time)

Product health metrics (user-facing)

  • Search success rate — % of queries that surface the correct file in top 3 results
  • Rename suggestion acceptance rate — signals whether suggestions match user intent
  • 7-day and 30-day retention — Alfie must become habitual, not occasional
  • Optimization score improvement over first 90 days

The primary metric is dataset quality, not revenue. Alfie is optimized to build an irreplaceable behavioral corpus. Revenue validates product-market fit and sustains development; dataset depth drives acquisition value.

Step 8

Agentic Commerce and Future Vision

Phase 4 introduces Alfie's agentic commerce layer — a capability set that transforms Alfie from a file intelligence tool into an ambient productivity agent that acts on file context.

Agentic actions

  • Contract review trigger — Alfie detects an agreement or contract file and surfaces relevant review tools, previous versions, or counterparty context
  • Invoice and receipt processing — identifies financial documents and offers routing to accounting software or expense systems
  • Research packaging — groups related files into shareable briefings without manual assembly
  • Renewal detection — surfaces subscription agreements nearing renewal dates with renewal options

Why this strengthens the acquisition thesis

Agentic commerce turns Alfie's intent graph into a commerce signal layer — Apple gains not just file behavioral data but purchase intent mapped to document context. For an Apple Intelligence strategy, this is the missing consumer data layer.

Alfie's long-term vision: every file becomes an intelligent object that knows what it is, what you need to do with it, and when — before you ask.
